# 画面要件定義書:FIRE目標・シミュレーション設定系画面(B8〜B9)

## 1. 位置付け

本ドキュメントは [画面一覧・画面遷移図](./screen-list-and-transitions.md) 2.4節のFIRE目標・シミュレーション設定系画面(B8〜B9)について、画面ごとの要件を詳細化したものである。機能全体の方針は [FIRE-FIRE 要件定義書](./fire-asset-management-requirements.md) 4.6〜4.7節を参照。

**到達予測日の算出は本書「到達予測日の算出」節が正本**とする。表示するのは [B1 ダッシュボード画面](./screen-requirements-dashboard.md#b1-ダッシュボード画面) だが、入力(目標資産額・対象分類・毎月の積立額はB8、資産種別ごとの想定利回りはB9)がこの2画面に分かれており、どちらかの画面の節に置くともう一方が従属して読めなくなるため。B1側には表示の要件だけを置き、算出そのものはここを参照する。

## B8. FIRE目標設定画面

- **画面目的**: FIRE達成目標を設定する。目標資産額の直接設定、または年間支出額からの逆算を切り替えて設定できる

| 区分 | 項目 |
|---|---|
| 表示項目 | 現在有効な設定方式、現在資産額との比較(参考表示。対象分類名を併記) |
| 入力項目 | 達成度の対象分類(タブ共通)、毎月の積立額(タブ共通) / 【直接入力タブ】目標資産額 / 【逆算タブ】想定年間支出額、逆算係数(4%ルール等、デフォルト値ありで編集可能) |
| 主な操作 | 達成度の対象分類の選択、毎月の積立額の入力、タブ切替(直接入力 / 逆算)、「保存」ボタン |

**遷移条件**

- タブ切替時、切替前に入力した値は両タブとも保持される(タブを行き来しても値は消えない)
- 保存成功 → **B1 ダッシュボード画面** へ遷移し、FIRE達成度ゲージ/到達予測日に反映結果を確認できる
- 未入力・数値形式不正等のバリデーションエラー → インラインエラー表示、遷移しない

**達成度の対象分類**

達成度の分子(現在資産額)をどの資産の範囲で数えるかを、[B4 資産分類マスタ設定画面](./screen-requirements-dashboard.md#b4-資産分類マスタ設定画面) で登録した分類軸から選ぶ。設定した範囲は [B1](./screen-requirements-dashboard.md#b1-ダッシュボード画面) のFIRE達成度ゲージと、この画面の参考表示の両方に効く。

- 選択肢は「**総資産(マネーフォワードの合計)**」+ B4で登録済みの分類軸。既定は「総資産(マネーフォワードの合計)」とし、未設定の状態がこれに当たる
- **タブの外に置き、両方式で共通の設定とする。** 目標資産額の決め方(直接入力/逆算)と、比較する資産の範囲は別の話であり、方式ごとに別々の対象分類を持つと切り替えたときに達成率が理由なく変わる
- 保存先はFIRE目標と同じドキュメント(`users/{uid}/settings/fireGoal`)とする。目標額と対象分類は「何に対する目標か」を1組で表すもので、別々に保存すると片方だけ古い状態になりうる
- 参考表示の現在資産額・達成率には**対象分類名を併記する**(例:「現在資産額 49,600,000円(投資性資産)」)。B1のゲージと同じ値・同じ表記にし、画面によって違う数字が出ないようにする
- **参考表示は、保存済みではなく「選択中(未保存)」の対象分類で集計する。** 分類を選び直した時点で現在資産額と達成率が動くので、保存する前にどの範囲で見ることになるかを確かめられる。保存済みの値で出すと、保存してB1へ遷移するまで結果が分からない
- 現在資産額の取得に失敗しても**目標の設定は続けられる**(参考表示だけが出ない)。目標額を決めること自体は現在資産額に依存しないため、参考表示の失敗で入力全体を止めない
- B4に分類軸が1件も無い場合(CSV未取込等)は「総資産(マネーフォワードの合計)」のみを選べる状態にし、B4への導線を添える。分類軸が無いこと自体はエラーではないため、保存はできる
- 保存済みの対象分類がB4で削除されていた場合は、画面を開いた時点で「総資産(マネーフォワードの合計)」を選択した状態に戻し、その旨を表示する。存在しない選択肢を選択中として出すことはできず、黙って戻すと設定し直したことに気付けないため
- 選択肢からの選択なので入力形式のエラーは発生しないが、保存時に存在しない分類軸IDが渡された場合は保存を拒否する
- 対象分類を変えても目標資産額(直接入力・逆算のいずれも)は変わらない。変わるのは達成率と到達予測日だけ
- 対象分類に**負債を集計対象に含む分類軸**([B4](./screen-requirements-dashboard.md#b4-資産分類マスタ設定画面))を選んだ場合、現在資産額は負債控除後の額になる。「現在資産額」というラベルは分類軸によって出し分けず、何を数えた額かは併記する対象分類名で示す(B1のゲージと同じ扱い)。既定の「総資産(マネーフォワードの合計)」に負債は含まれない — マネーフォワードが負債をCSVに出力しないため、負債を達成度に効かせるには負債を含む分類軸を作って選ぶ必要がある
- 負債が資産を上回って現在資産額がマイナスになった場合、**達成率は0%に丸め、現在資産額の金額はマイナスのまま出す**。負債が資産を上回っている旨も添える。丸め方・注記の理由はB1のゲージと同じで、正は [screen-requirements-dashboard.md](./screen-requirements-dashboard.md) B1「負債を含む分類軸の集計」に置く。**この画面で独自に丸め方を決めない** — 同じ設定に対して画面ごとに違う達成率が出るのを避けるため

**毎月の積立額**

到達予測日の算出に使う「毎月いくら積み増すか」を、この画面で手入力する(算出上の扱いは後述「到達予測日の算出」)。**この欄は未実装で、[B8-3](https://trello.com/c/rsheJOd0) で実装する。**

- **タブの外に置き、両方式で共通の設定とする。** 対象分類と同じ理由で、目標額の決め方によって積立額が変わる理由が無い
- 保存先も目標額・対象分類と同じ `users/{uid}/settings/fireGoal` とする
- **既定値として、前月の月次収支(収入 − 支出)を初期表示する。** 要件定義書 4.6 の「現在のペースに基づく」を、手入力のまま満たすための出発点。ユーザーはそのまま保存しても、上書きしてもよい
  - 集計対象は [B1](./screen-requirements-dashboard.md#b1-ダッシュボード画面) の収支サマリと同じ(振替・計算対象外の行を除く。[入出金明細CSV取込 要件定義書](./transaction-import-requirements.md) 5章)。同じ月について画面ごとに違う収支が出ないようにするため
  - **当月ではなく前月を採る。** 当月は月初だと数日分しか無く、その月の収支として意味を成さない。前月なら1ヶ月分が揃っている
  - 読むのは**前月の1ヶ月分だけ**とする(B1の収支サマリと同じ制約。[入出金明細CSV取込 要件定義書](./transaction-import-requirements.md) 8章)。複数月を読んで平均を取る案は採らない — B1が1ヶ月しか読まないと決めた理由(取引は際限なく増える)がそのまま当てはまる
  - 前月の取引が0件(未取込・その月に取引が無い)の場合は初期値を提示せず空欄にし、提示できなかった旨を添える。0円を提示すると「収支がちょうど0だった」と読める
  - **提示するのは画面を開いた時点の初期値だけで、保存後に追従して変わることはしない。** 保存した値がそのまま予測に使われる、という関係を崩さないため
- 未入力は0(積立なし)として扱う。**マイナスも受け付ける** — 取り崩しの局面を表せるようにするため。マイナスの場合は資産が減る方向に効き、到達しない結果になりうる(後述「到達見込みなし」)
- 形式は他の金額欄と揃える(半角数字のみ、カンマ区切り・全角数字・指数表記は受け付けない)。形式不正はインラインエラー

## B9. 想定利回り・リスク設定画面

- **画面目的**: 資産種別ごとに想定利回り・リスクレベルを手動設定する。設定値はFIRE到達予測の入力パラメータと、ダッシュボードでのリスク可視化の両方に反映される

| 区分 | 項目 |
|---|---|
| 表示項目 | 資産種別一覧(資産種別名、現在残高) |
| 入力項目 | 資産種別ごとの想定利回り(年率%)、リスクレベル |
| 主な操作 | 一覧内でのインライン編集、「保存」ボタン |

**遷移条件**

- 保存成功 → **B1 ダッシュボード画面** へ遷移し、FIRE到達予測・リスク可視化に反映結果を確認できる
- 数値形式不正等のバリデーションエラー → インラインエラー表示、遷移しない

**設定の単位は資産種別**

一覧の行は、**直近の資産残高に現れる資産種別**(マネーフォワードのCSVの列名そのもの)で作る。口座単位ではない。

- マネーフォワードのCSVは資産種別の列しか出力せず、口座別の残高を持つ手段がアプリ側に無い。口座単位にするには残高の入力を別に設けることになり、CSV取込で完結するという4.2の方針から外れる
- 資産種別名は動的なマスタデータで、アプリ側にIDを振る場所が無い。したがって保存も**資産種別名をキー**にする(`assetSnapshots` の `byType` と同じ扱い)
- 現在残高は**直近の集計日の値**をそのまま出す(参考表示。入力欄ではない)
- **行の並びは現在残高の降順**とする。CSVの列順や名前順ではない。額の大きい資産種別ほど想定利回りが予測に効くため、先に目に入る順に並べる
- 保存済みの設定のうち**解釈できない資産種別が混じっていた場合は、その1件だけを飛ばして残りを表示する**。1件の不整合で設定がすべて空になると、そのまま保存し直したときに残りの全部を消すことになる(取込履歴と同じ扱い)
- 資産種別はCSVの列の顔ぶれで決まるため、**保有しなくなった資産種別は列ごと消え、一覧からも消える**。この場合も保存済みの設定は**そのまま残す**(後述「一覧に出ていない資産種別」)
- CSVを一度も取り込んでいない場合、一覧に出せる行が無い。「データがありません」で止めず、[B2 CSV取込画面](./screen-requirements-dashboard.md#b2-csv取込画面) への導線を添える

**入力項目の詳細**

| 項目 | 形式 | 必須 |
|---|---|---|
| 想定利回り | 年率のパーセント(4%なら `4`)。半角数字のみ、小数可、マイナス可 | 任意 |
| リスクレベル | 低 / 中 / 高 / 未設定 の4択 | 任意 |

- **どちらの欄も必須にしない。** 一覧に並ぶのは取り込んだ資産種別すべてで、その全部に想定を置けるとは限らない。片方だけ設定した状態(利回りは決めたがリスクはまだ、等)もそのまま保存できる
- 両方が未設定の行は**保存しない**。一度も触っていない資産種別の分まで空の想定値が並ぶと、保存済みの設定と区別が付かなくなる
- 想定利回りの**絶対値は100%以内**とする。年率100%を超える想定より、桁の打ち間違い(5を500と打つ等)のほうがはるかに起こりやすく、極端な値がそのまま到達予測に効く
- **マイナスの想定利回りを許す**のは、元本割れを見込む資産に「年率-1%」のような想定を置けるようにするため
- カンマ区切り・全角数字・指数表記は受け付けない(B7・B8の金額欄と揃える)。形式・範囲のエラーは**その行にインライン表示**する
- リスクレベルは3段階に留める。手で置く前提値であって計測値ではなく、段階を細かくしても入力の精度は上がらないため
- リスクレベルの表示は**色だけに頼らず形状(アイコン)と文字を併用する**([DESIGN.md](../DESIGN.md) 3章)。意味を運ぶのは形状と文字で、色は補助に留める

**一覧に出ていない資産種別**

保存時、**一覧に出ていない資産種別の保存済み設定はそのまま引き継ぐ**(消さない)。

- 資産種別はその月に保有していなければCSVの列ごと消えるため、画面に出ていない間に保存したというだけで以前に置いた想定利回りが消えるのは避ける
- 逆に、保存済みの設定にしか無い資産種別を一覧の行にはしない。直近の残高が無い以上「現在残高」を出せず、表示項目を満たさない行になる
- 保存できる資産種別の件数には上限を置く(`ASSUMPTION_ENTRIES_MAX` = 200)。資産種別は動的で件数を決め打ちできないため、壊れた書き込みを弾く歯止めとして余裕を持たせた値にする。判定は `firestore.rules` 側で行う(要件定義書 8.1)
- **保存はドキュメントを丸ごと置き換える**(`merge` しない)。画面が全件をまとめて編集するため差分更新にする理由が無く、`merge` にすると空欄へ戻したはずの欄が前回の値のまま残る。一覧に出ていない資産種別を引き継ぐのは、書き込む値を組み立てる時点で行う(上記)

**不動産・負債の想定は置けない**

一覧に並ぶのはCSV由来の資産種別だけで、手入力の物件([B5〜B7](./screen-requirements-real-estate.md))と負債([B11](./screen-requirements-dashboard.md#b11-負債入力画面))には想定利回りもリスクレベルも置けない。

- 物件を一覧に足す案は採らない。物件の時価は手動更新が前提(要件定義書 4.5)で、時価に利回りを掛けて自動で育てると、手動更新した値との関係が説明できなくなる
- 負債も同じで、残債から返済ペースを導かないことが要件定義書 4.8 の「自動計算は行わない」で決まっている
- したがって**到達予測では物件・負債を全期間で据え置く**(後述「到達予測日の算出」)

## 到達予測日の算出

FIRE達成度ゲージに併記する到達予測日([B1](./screen-requirements-dashboard.md#b1-ダッシュボード画面))の算出方式を定める。表示の要件はB1側にある。

**本節は未実装で、[B1-16](https://trello.com/c/KddjFTnU) で実装する。** 現状の `buildFireProgress` は `projectedAchievementDate: null` を返し続けており、B1には常に「算出できません」が出ている。入力に使う毎月の積立額(B8)も未実装なので、[B8-3](https://trello.com/c/rsheJOd0) を先に入れる。

### 入力

| 何 | どこから |
|---|---|
| 目標資産額 | B8(直接入力、または年間支出額と逆算係数から算出) |
| 現在資産額と、その内訳 | B8で設定した**達成度の対象分類**での集計([B1](./screen-requirements-dashboard.md#b1-ダッシュボード画面)「FIRE達成度の現在資産額(対象分類)」) |
| 資産種別ごとの想定利回り | B9 |
| 毎月の積立額 | B8 |

### 手順

**起点は当月**とし、月単位で先へ進める。表示が「2033年4月頃」の粒度である以上、日単位まで刻む意味が無い。

1. 対象分類に含まれる**資産種別ごと**に、その残高へ月次の成長率を掛ける
2. 積立額を加える
3. 対象の**物件の額(利ざや または 時価)と負債の残債は、そのままの値を据え置く**
4. 合計が目標資産額に達した最初の月を到達月とする

月次の成長率は **`(1 + 年率 ÷ 100) ^ (1/12)`** とする。年1回の複利ではなく月次にするのは、積立が毎月入るためと、答えを月単位で出すためである。単利は採らない — 長期の予測で実態から離れが大きくなるうえ、4.6が想定する資産成長の見方と合わない。

**積立額には利回りを掛けない。** 積んだ分がどの資産種別に入るかを尋ねる欄が無く、推測で利回りの高い資産種別に積むと予測が楽観へ倒れる。据え置きの現金として積み上がる扱いにする(実際より遅く出る方向であり、外すなら安全な側)。

**想定利回りが未設定の資産種別は年率0%として扱う。** 予測から除外はしない — その残高は現在資産額に入っており、除外すると予測の初月が現在資産額と食い違う。

**対象分類が既定(総資産)のときは、資産種別の内訳とCSVの「合計(円)」列の差額を年率0%で据え置く。** 既定の現在資産額はCSVの合計をそのまま採る決まりで(B1「FIRE達成度の現在資産額(対象分類)」)、合計には資産種別の列に現れない額が含まれうる。何の資産か分からない額に利回りを当てられないため据え置き、これにより**予測の初月は必ず現在資産額と一致する**。

### 結果の区別

到達予測日の欄に出す状態は**3つ**とする。「目標に達する月」と「設定した結果として届かない」を同じ空欄で表すと区別が付かない。

| 状態 | 条件 | 表示 |
|---|---|---|
| 到達予測日 | 目標に達する月が求まった | 「2033年4月頃」 |
| 達成済み | 現在資産額が既に目標資産額以上 | 「達成済み」 |
| 到達見込みなし | 打ち切り月まで進めても目標に届かない | 「到達見込みなし」 |

- **打ち切りは600ヶ月(50年)先**とする。上限を置かないと、資産がまったく増えない設定で終わらない。50年は個人のFIRE計画として現実的な上限を十分に超える
- 「達成済み」は、現在資産額 ≥ 目標資産額 を満たした時点で**過去日付や0ヶ月を出さずに**この文言へ倒す。達成後に目標を上げ直せば通常の予測へ戻る
- 「到達見込みなし」になるのは、対象の資産種別の想定利回りがすべて未設定(=0%)で積立額も0以下の場合か、積立額のマイナスが利回りの伸びを上回る場合である。**B9・B8への導線を添える** — 前提を置けば予測が出ることが分かるようにするため

**「前提が足りない」を4つ目の状態にしない。** 到達予測日の欄が出ている時点で、足りない前提は既に別の形で画面に出ている。

- **目標資産額が未設定・0以下のときは、FIRE達成度のカードごと空状態(「FIRE目標が未設定です」)になり、到達予測日の欄そのものが現れない**(B1の既存の扱い)。ここで予測側だけが独自に「算出できません」を出す場面が無い
- **資産残高が未取込のときは現在資産額を0円として扱う**(B1「FIRE達成度の現在資産額(対象分類)」)。予測もその0円から始めればよく、積立額があれば到達月は求まる。**未取込を理由に予測を止めない** — 止めると、ゲージだけが0%を出して予測は何も言わない、という中途半端な状態になる
- 現行の「算出できません」は、到達予測を実装していない現在の表示である。実装後は**前提の解決そのものに失敗した場合の保険**としてのみ残し、通常の運用で出る状態とはしない

### 精度についての注記

この予測は**置いた前提のとおりに資産が育った場合の目安**であり、確定した日付ではない。表示に「頃」を添えるのはそのためで、日付までは出さない。

- 想定利回りは手で置いた値であり、実績とは無関係である
- 積立額は前月の収支を出発点にした固定値で、収入・支出の変化には追従しない
- 物件の時価・負債の残債は据え置きのため、ローンの返済が進んでも予測は良くならない
