# 画面要件定義書:アカウント系画面(B10)

## 1. 位置付け

本ドキュメントは [画面一覧・画面遷移図](./screen-list-and-transitions.md) 2.5節のアカウント系画面(B10)について、画面ごとの要件を詳細化したものである。認証方式の全体方針は [ログイン画面・認証機能 要件定義書](./auth-login-requirements.md) を参照。

## B10. アカウント設定画面

- **画面目的**: ログイン後にパスワード変更・2FA再設定などのアカウント関連設定を行う

| 区分 | 項目 |
|---|---|
| 表示項目 | 登録メールアドレス、2FA設定状況、連携済みログイン方法の一覧 †、リカバリーコードの残り本数 ‡ |
| 入力項目 | なし(操作はボタン起点。パスワードの現在値入力は不要) |
| 主な操作 | 「パスワード変更メールを送信する」ボタン、「2FAを再設定する」ボタン、「Googleと連携する」/「連携を解除する」ボタン †、「リカバリーコードを再発行する」ボタン ‡ |

**遷移条件**

- 「パスワード変更メールを送信する」押下 → **A6 パスワードをお忘れの方画面**〜**A7 パスワード再設定画面** と同じリセットメールフローを使用し、登録メールアドレス宛にリセットリンクを送信する(現在のパスワード入力は不要)
- 「2FAを再設定する」押下 → 本人確認(パスワード再入力等)を経て現在の2FA設定を無効化し、**A3 2FA登録画面** と同様のQRコード登録フローを再実行する
- 2FA再設定完了後 → **B1 ダッシュボード画面** へ遷移
- 「リカバリーコードを再発行する」押下 → 画面遷移せず、新しいコード一覧を画面内に表示する(A3の表示と同じく平文はその場限り。ダウンロードも同様に用意する)。以前のコードはすべて無効になる ‡

### リカバリーコードの再発行 ‡

2FAリカバリーコード([auth-login-requirements.md](./auth-login-requirements.md) 3.3)の再発行導線をこの画面に置く。以前のコードをすべて無効にして8本を作り直し、平文をその場で一度だけ表示する。

再発行にも「2FAを再設定する」と同じ**本人確認(パスワード再入力等)を求める**。再発行は以前のコードを無効化するため、セッションを乗っ取られた状態で実行されると、正規の利用者が持っているコードだけが使えなくなる(2FAそのものの突破には繋がらないが、認証アプリ紛失時の復旧手段を失う)。現状の `generateMfaRecoveryCodes` はサインイン済みであることしか確認していないため、この画面を実装する際に本人確認の要求を追加する。

> ‡ **B10側のUIは未実装。** Trelloカード [A3-2] 2FAリカバリーコード ではA3の発行・A5の使用と、発行/再発行に使うCloud Functions(`generateMfaRecoveryCodes`)までを実装済み。B10の画面自体がまだ無いため、この画面を作るカードで既存のcallableを呼ぶUI(残り本数の表示と再発行ボタン)を追加する。残り本数はFirestoreを直接読ませず、callableの応答から得る(セキュリティルールでクライアントからの参照を全面的に拒否しているため)。

### 連携アカウントの管理 †

ソーシャルログイン([auth-login-requirements.md](./auth-login-requirements.md) 3.8)で連携できるログイン方法を、この画面から確認・追加・解除する。

| 表示・操作 | 仕様 |
|---|---|
| ログイン方法の一覧 | 「メールアドレス / パスワード」「Google」を行として表示し、各行に連携状況(連携済み / 未連携)を示す。Google行には連携済みのGoogleアカウントのメールアドレスを併記する |
| 「Googleと連携する」 | 未連携の場合に表示。Googleのサインインポップアップを開き、成功したら現在のアカウントにGoogleを連携する |
| 「連携を解除する」 | 連携済みの場合に表示。確認ダイアログを挟んでから解除する |

**制約・エラー**

- **最後に残った1つのログイン方法は解除できない**。解除するとアカウントにサインインする手段が無くなるため、ボタンを無効化し理由を併記する(例: Googleのみで作成したアカウントはGoogleの解除不可)
- 連携しようとしたGoogleアカウントが**別のFIRE-FIREアカウントに既に紐付いている**場合(`auth/credential-already-in-use`)は連携できない。画面内にその旨をエラー表示する
- 連携しようとしたGoogleアカウントのメールアドレスが**このアカウントの登録メールアドレスと異なる**場合も連携自体は可能だが、ログイン通知([auth-login-requirements.md](./auth-login-requirements.md) 3.6)の宛先は登録メールアドレスのままである旨を注記する
- 解除・連携のいずれも、成否を画面内のメッセージで伝え、画面遷移はしない

> † **連携アカウントの管理は未実装。** Trelloカード [A8-2] 連携アカウント管理(B10) で扱う。[A8] ソーシャルログイン(Google)対応 ではA1・A4のログイン導線とA8 アカウント連携画面までを対象とし、B10側のUIは本ドキュメントの記述どおり後続カードで実装する。
