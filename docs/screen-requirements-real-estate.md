# 画面要件定義書:不動産管理系画面(B5〜B7)

## 1. 位置付け

本ドキュメントは [画面一覧・画面遷移図](./screen-list-and-transitions.md) 2.3節の不動産管理系画面(B5〜B7)について、画面ごとの要件を詳細化したものである。機能全体の方針は [FIRE-FIRE 要件定義書](./fire-asset-management-requirements.md) 4.5節を参照。

**実装状況**: B5〜B7は実装済みで、`users/{uid}/properties/{propertyId}` に対して読み書きしている。**物件の削除だけが未実装**(後掲「[物件の削除](#物件の削除未実装)」)。

## 2. 3画面に共通する扱い

### 保存する値と計算する値

**利ざや(時価 - ローン残高)と賃貸収支(賃貸収入 - 賃貸支出)は保存しない。** 表示のたびに時価・ローン残高・賃貸収入・賃貸支出から計算する。時価を更新したのに保存済みの計算結果が古いまま、という食い違いを作らないため。

### 収益物件かどうかの判定

**賃貸収入/支出を持っているかどうか、その1つで決まる。** 「収益物件である」という区分のフラグを金額とは別に持たない。両方を持つと「収益物件なのに金額が無い」「非収益物件なのに金額が残っている」という食い違いが作れてしまうため。B7の「収益物件として登録」チェックボックスのオン/オフがそのまま金額の有無に対応する。

### 取得・保存に失敗したとき

失敗の理由(未ログイン / Firebaseの設定が読めない / 権限なし / 不明)に応じた文言を表示し、遷移しない。文言の作り分けは [B4 資産分類マスタ設定画面](./screen-requirements-dashboard.md#b4-資産分類マスタ設定画面) と同じ考え方に揃える。

### 読み込み中の表示

3画面とも、物件を読んでいる間は**スケルトン**を出す(取得はブラウザ側のFirebase SDKに依るため、初回描画では値が無い)。B7の編集モードは**取得できるまでフォームを描かない** — 空のフォームが一瞬見えてから値が入ると、書き換えたのか読み込み中なのかが分からなくなるため。

### 金額の色と符号

正負で色を変える金額(利ざや・賃貸収支)には、**必ず符号を添える**。色だけに意味を持たせないため([DESIGN.md](../DESIGN.md))。

- **利ざや**: 正負で文字色と背景を変える。ただし残高と同じ「量」なので、プラス側に `+` は付けない(負のときに `- ¥` が付く)
- **賃貸収支**: 符号そのものが意味を持つ値なので、**プラスでも符号を出す**
- 時価・ローン残高: 色を付けない

### 入力値の検査

下記の入力の制約(B7)は、画面側(zod)と `firestore.rules` の `isValidProperty()` の**両方**で検査する。片方だけを直して食い違わせないこと。**最終更新日が保存した日そのものであることだけはルールで検査していない**(形は `yyyy-MM-dd` まで見ている) — [要件定義書 8.1](./fire-asset-management-requirements.md#81-クライアントだけが担保している制約) に理由とともに載せてある。

## B5. 不動産一覧画面

- **画面目的**: 登録済み物件の一覧表示

| 区分 | 項目 |
|---|---|
| 表示項目 | 物件名、所在地(簡略)、時価、ローン残高 |
| 入力項目 | なし |
| 主な操作 | 「新規登録」ボタン、物件行のクリック |

**遷移条件**

- 「新規登録」ボタン押下 → **B7 不動産登録・編集画面**(新規登録モード)へ遷移
- 物件行クリック → **B6 不動産詳細画面** へ遷移
- 利ざや(時価-ローン残高)は一覧画面には表示せず、B6でのみ表示する

**表示項目の補足**

- **所在地は簡略表記に落として表示する**。B7で登録した住所をそのまま保持し、一覧では**都道府県+市区町村まで**に切る(「東京都渋谷区」)。番地・部屋番号まで並べると物件名が読み取りにくくなるため。登録した住所そのものはB6で確認できる
  - 都道府県から始まらない表記(海外の住所など)は**切らずにそのまま表示する**。当てはまらない形を勝手に削って意味を変えないため
  - 所在地は任意入力なので、未入力の物件は空欄で並ぶ
- **行は参照専用**で、編集・削除の導線を持たない(編集はB6を経由してB7へ入る)
- 画面上部に**利ざやをB6で確認できる旨の説明文**を置く。一覧に出さない値がどこで見られるかを示すため

**一覧の並び順**

**登録順(古い順)に固定する。** 並び替えの指定は無い。金額順や更新日順にすると、時価を更新するたびに一覧での位置が変わり、目当ての物件を探しにくくなるため。編集では並び順を変えない(登録日時は編集で更新しない。`firestore.rules` 側でも変更を拒否している)。

**物件が1件も登録されていないとき**

- 「登録済みの物件がまだありません。」と、**B7 新規登録モード**への導線を表示する
- 導線のラベルは画面上部の「新規登録」ボタンとあえて変える。同じ文言のボタンが縦に2つ並ぶと、別の操作があるように見えるため

**取得に失敗したとき・解釈できない物件があるとき**

- 前掲「取得・保存に失敗したとき」の文言を表示し、一覧は出さない
- **解釈できない物件が混じっていた場合は、その1件だけを一覧から落として残りを表示する**。1件の不整合で一覧全体を空にしないため(B2の取込履歴と同じ扱い)

## B6. 不動産詳細画面

- **画面目的**: 物件の詳細情報と利ざやを確認する

| 区分 | 項目 |
|---|---|
| 表示項目 | 物件基本情報(物件名、所在地、**最終更新日**)、時価、ローン残高、**利ざや(時価-ローン残高、自動計算)**、収益物件の場合は賃貸収入/支出(**月額**)とその収支 |
| 入力項目 | なし(参照専用) |
| 主な操作 | 「編集」ボタン、「一覧に戻る」リンク |

**表示項目の補足**

- **最終更新日**: B7で保存した日付。時価もローン残高も手動更新(要件定義書 4.5)であり、いつ時点の値か分からないと利ざやをどこまで信用してよいか判断できないため表示する
- **賃貸収入/支出の単位は月額**とする。家賃・管理費とも月単位で発生するため。年額での表示・入力が必要になった場合はB7の入力項目と合わせて拡張する
- 収益物件かどうかは賃貸収入/支出の登録有無で決まる(B7の「収益物件として登録」チェックボックスに対応)。収益物件でない物件では賃貸収支の表示自体を行わない
  - 収益物件には**物件名の下に「収益物件」ラベル**を添える。賃貸収支セクションの有無だけでは、画面を上から読むまで(スクロールしないと)区別が付かないため。収益物件でない物件には何も出さない
  - この行には**簡略表記の所在地**(B5と同じ形)と並べて「所在地・収益物件」と出す。所在地は任意入力で空のことがあるため、**区切りの「・」は両方が揃ったときだけ**入れる
  - 一方、**物件基本情報カードには登録された住所をそのまま**出す(簡略にしない)。切らずに確認できる場所をこの画面に1つ持たせるため
- 利ざやは保存された値ではなく、表示のたびに時価とローン残高から計算する。オーバーローン(ローン残高 > 時価)の物件では負の値になる
  - **負の値を0で止めない。** 符号を付けてそのまま表示する。オーバーローンであること自体が読み取りたい情報であり、0に丸めると健全な物件と区別が付かなくなるため
  - 見出しには「(自動計算)」と計算式(時価 - ローン残高)を添える。手で入力した値ではないこと、何から引いた値かが画面上で分かるようにするため
- **賃貸収支(賃貸収入 - 賃貸支出)も月額**で、支出が上回る月は負になる。利ざやと同じくその場で計算し、保存しない

**遷移条件**

- 「編集」ボタン押下 → **B7 不動産登録・編集画面**(編集モード、既存値をプリセット)へ遷移
- 「一覧に戻る」リンク押下 → **B5 不動産一覧画面** へ遷移
- 指定された物件が存在しない(削除済みの物件をブックマーク等から開いた、URLが正しくない) → 「物件が見つかりません」の案内と**B5 不動産一覧画面**への導線を表示し、遷移しない
  - **解釈できない物件も「見つかりません」と同じ扱いにする。** どちらもその物件を表示できないことに変わりはなく、利用者側に取れる手が「一覧に戻る」しかないため。「取得に失敗しました」とは出し分ける(そちらは時間をおいて再試行すれば直りうる)

## B7. 不動産登録・編集画面

- **画面目的**: 物件基本情報・時価・ローン残高・(収益物件の場合)賃貸収入/支出を登録・編集する

| 区分 | 項目 |
|---|---|
| 表示項目 | (編集時)既存の登録値 |
| 入力項目 | 物件名、所在地、時価、ローン残高、「収益物件として登録」チェックボックス、(チェックオン時のみ表示)賃貸収入(月額)、賃貸支出(月額) |
| 主な操作 | 「保存」ボタン、「キャンセル」リンク |

**入力項目の補足**

- ローン残高は**物件の利ざやを出すための項目**で、ダッシュボードの集計には入らない。ダッシュボードで資産から差し引く負債は [B11 負債入力画面](./screen-requirements-dashboard.md#b11-負債入力画面) で別に登録する。同じ住宅ローンを両方に入れても二重に差し引かれることはない(B11「不動産のローン残高(B7)との関係」)
- 賃貸収入/支出の単位は**月額**(B6の表示と揃える)
- **最終更新日は入力項目ではなく、保存時に自動で更新する**(B6で表示する)
- 「収益物件として登録」をオフにして保存した場合、賃貸収入/支出は保持しない。B6は賃貸収支の表示自体を行わない

**入力の制約**

| 項目 | 必須 | 制約 |
|---|---|---|
| 物件名 | 必須 | 60文字以内 |
| 所在地 | **任意**(未入力可) | 100文字以内 |
| 時価 / ローン残高 | 必須 | 半角数字のみ・12桁以内(999,999,999,999円) |
| 賃貸収入 / 賃貸支出(月額) | 「収益物件として登録」がオンのときのみ必須 | 同上 |

- 金額は**円単位**で入力する。入力欄の見出しに単位を添え、万円単位と取り違えられないようにする
- **カンマ区切り(`18,400,000`)・全角数字は受け付けずエラーにする。** 入力形式を1つに絞り、保存された金額と入力した文字列が食い違う余地を作らないため
- 12桁の上限は、桁の打ち間違い(0を余分に打つ・単位を取り違える)を弾くための歯止めである。個人が保有する不動産の時価・ローン残高としては12桁で十分に収まる
- 所在地を任意にしているのは、物件名だけで区別が付く運用を妨げないため。未入力の物件はB5で空欄になる

**「収益物件として登録」を切り替えたとき**

- オフにすると賃貸の入力欄は**隠すが、書きかけの値はフォームに残す**。誤ってオフにしてもチェックを戻せばそのまま使える
- オフの間は賃貸の2欄を**検証しない**(書きかけの値が残っていても保存を妨げない)
- オフのまま保存した場合、賃貸収入/支出は保存しない。**編集で収益物件から外した物件は、以前の金額も残らない**

**保存**

- **保存中は「保存」ボタンを押せなくする。** 保存に成功した場合はB6へ遷移し終わるまで押せないままにする(遷移までの間だけ押せる状態に戻ると、二重に登録できてしまう)
- 「キャンセル」は保存中も押せるままにする。書き込みは成立するかしないかのどちらかで、中途半端な物件は残らない
- 保存に成功したらトーストで知らせる。**新規登録と編集で文言を分ける**(「登録しました」/「更新しました」)
- 保存に失敗したらフォーム上にエラーを表示し、遷移しない。**入力値は保持する**(打ち直させないため)
- **最終更新日にはサーバー時刻ではなく端末の日付(`yyyy-MM-dd`)を入れる。** B6が表示するのは日付だけで時刻の精度を必要とせず、サーバー時刻は書き込み直後に値が確定しないため、保存してB6に戻った直後だけ最終更新日が空になる
- **登録日時は編集で更新しない。** B5の並び順(登録順)が編集のたびに入れ替わらないようにするため
- 保存に成功したら、**一覧(B5)と当の物件(B6)のキャッシュを取り直す**。新規登録の直後にB5へ戻って登録した物件が並んでいない、編集の直後にB6が古い値を出す、という状態を作らないため(新規登録では一覧だけ、編集では両方)

**遷移条件**

- 保存成功(新規登録) → **B6 不動産詳細画面**(登録した物件)へ遷移
- 保存成功(編集) → **B6 不動産詳細画面**(該当物件)へ遷移
- 「キャンセル」押下 → 遷移元の画面(新規登録時は**B5**、編集時は**B6**)に戻る
- 必須項目未入力・数値形式不正等のバリデーションエラー → インラインエラー表示、遷移しない
- 編集モードで指定された物件が存在しない・解釈できない → B6と同じ「物件が見つかりません」を表示し、フォームを出さない

## 物件の削除(未実装)

**この節は未実装である。** B5〜B7のどこにも削除の操作が無く、`firestore.rules` の `properties` も `allow delete: if false` のままである。一方でB6には「削除済みの物件をブックマーク等から開いた」場合の要件があり、**削除できないのに削除済みの物件を想定している**状態になっている。負債(B11)は削除できるため、不動産だけ手段が無い。実装は [B6-1](https://trello.com/c/0Frlp1Q1) で行う。

- **操作は B6 不動産詳細画面に置く。**「編集」ボタンの隣に「削除」を置き、B5 一覧には置かない
  - B5は参照専用で行全体がB6へのリンクになっており、行の中に破壊的な操作を混ぜると誤操作で消えるため
  - 削除の前に時価・ローン残高・利ざやを確認できる場所がB6であるため
- **確認ダイアログを必ず挟む**(B11の負債削除と同じ扱い)。どの物件を消すのか分かるよう物件名を示す
- **削除は元に戻せない。** 論理削除(ゴミ箱)は設けない(B11と同じ)
- 削除に成功 → **B5 不動産一覧画面**へ遷移し、トーストで知らせる
  - このとき**一覧のキャッシュを取り直す**(B7の保存と同じ)。消したはずの物件が一覧に残っていると、削除できたのか判断できないため
- 削除に失敗 → B6に留まり、前掲「取得・保存に失敗したとき」の文言を表示する
- **他の画面への波及は無い。** 物件はダッシュボードの集計にも資産分類軸にも入らない([要件定義書](./fire-asset-management-requirements.md) 4.4・4.5)ため、削除しても他の画面の表示は変わらない。負債と違い分類軸から参照されることもないので、B4の「生きている負債を参照した軸を消させない」に相当する制約は不要である
- 削除済みの物件を開いたときの表示は、B6・B7の既定のとおり(「物件が見つかりません」)

## 今後の検討事項

| 項目 | 現状 | 保留の理由 |
|---|---|---|
| 物件の登録件数の上限 | **上限なし**。負債は50件(`DEBT_MAX_COUNT`)で止めている | 物件は手入力で1件ずつ増えるため、負債の一括保存と違って件数が跳ねない。単一ユーザー運用では実害が無い |
| 同一物件を複数のタブ・端末から同時に編集したとき | **後に保存した内容で上書きする**(後勝ち)。B7はフォーム全体を1回の保存で置き換えるため、他方の変更は黙って消える | 単一ユーザー運用のため許容する。B11の負債は同じ問題を実際に踏んで対処したが、あちらは1画面で全件をまとめて保存する作りで、影響範囲が物件1件に収まらなかった |
| 賃貸収入/支出の年額表示・入力 | 月額のみ | 家賃・管理費とも月単位で発生する。年額が要るようになったらB6の表示とB7の入力を揃えて拡張する |
| 1物件に複数のローンを紐付ける | 1物件1ローン | [要件定義書](./fire-asset-management-requirements.md) 4.5の将来拡張のまま |
| 時価の履歴 | **最新値のみ**。負債は残債の履歴を持つ | 資産推移グラフは物件を含めない(同 4.4)ため、過去時点の時価を必要とする画面が今のところ無い |
