# FIRE資産管理WEBアプリ 要件定義書

## 1. 概要・目的

個人のFIRE(Financial Independence, Retire Early)達成を支援するための資産管理WEBアプリケーションを開発する。
マネーフォワードからエクスポートしたCSVデータを取り込み、資産全体をダッシュボードとして可視化するとともに、FIRE目標に対する達成度・到達期間の予測を行う。

## 2. 想定ユーザー

- **初期リリース時点**: 開発者本人専用(シングルユーザー利用)
- **将来構想**: 第三者にも公開するSaaS化を見据える
  - 権限モデル(管理者/一般ユーザーなど)は現時点では未定義とし、将来の拡張項目として本ドキュメントに記録するのみに留める
  - 初期実装では認証(ログイン)機能のみを実装し、マルチテナント設計・ロール管理は行わない

## 3. 全体アーキテクチャ

| レイヤー | 技術・方針 |
|---|---|
| フロントエンド | Next.js(React)、アダプティブデザイン(PC/タブレット/スマホ対応) |
| バックエンド | サーバレス構成(Firebaseを想定) |
| 認証 | Firebase Authentication |
| データストア | Cloud Firestore(NoSQL)を想定。分類マスタ等は拡張しやすいスキーマとする |
| ファイルストレージ | Firebase Storage(CSVアップロードファイルの保管を想定) |
| ホスティング | 要決定(Vercel または Firebase Hosting) |
| 開発支援ツール | Claude Codeを契約し、実装効率化に活用 |

> 上記は「サーバレス/Firebase」という方針に基づく標準的な構成案であり、各サービスの詳細な選定(Firestore vs 他DB、ホスティング先など)は実装フェーズで確定する。

## 4. 機能要件

### 4.1 認証・ユーザー管理

- Firebase Authenticationによるログイン機能を実装する
- 初期リリースは本人専用のシングルユーザー運用
- 将来のSaaS化・複数ユーザー対応(権限モデル、データ分離方式)は本ドキュメントでは範囲外とし、別途設計する

### 4.2 マネーフォワードCSV連携

- **取込方式**
  - MVPでは手動アップロードのみ対応(CSVファイルをアプリ画面からアップロード)
  - 将来的に定期自動取得への対応を検討する(方式は未確定。マネーフォワード公式APIまたはスクレイピング等、実装コスト・利用規約を踏まえて別途検討)
- **取込対象データ**
  - 資産残高推移(各口座の日次/月次残高)
  - 入出金明細(取引データ) — 費目別の収支分析に必要なため取込対象に含める

### 4.3 資産分類(ポートフォリオの切り替え表示)

総資産ポートフォリオに加え、以下のような分類軸で切り替え表示できるようにする。

- 総資産
- 純金融資産
- 金融資産
- 投資性資産(投資信託 + 株式 + iDeCo)
- 流動限定金融資産(iDeCo + 小規模企業共済)

**設計上の要件**: 分類軸は開発中・運用中に追加される可能性があるため、コードにハードコードせず、マスタデータとして追加・編集可能な拡張性のある設計とする。

### 4.4 資産ダッシュボード

以下の指標・グラフを表示する。

- 総資産推移グラフ(時系列の折れ線グラフ)
- 分類別内訳(円グラフ・構成比、4.3の分類軸で切り替え可能)
- FIRE達成度ゲージ/到達予測日
- 収支サマリ(月次収支・費目別支出) — 入出金明細データを基に集計

### 4.5 不動産管理

- 複数物件の登録に対応する
- 管理項目
  - 物件基本情報
  - 時価(手動更新)
  - 住宅ローン残高
  - 賃貸収入/支出(収益物件に対応する場合)
- **利ざや計算**: 不動産時価 - 住宅ローン残高 を自動計算し表示する
- 1物件につき基本は1ローンを想定(複数ローンの紐付けなど詳細な構成は将来拡張)

### 4.6 FIRE目標設定・達成度・到達期間予測

以下2つの目標設定方式に両対応し、ユーザーが切り替えられるようにする。

1. **目標資産額を直接設定**: 例)「金融資産3,000万円」のようにゴール額を直接入力し、現在資産との差分・到達予測時期を計算
2. **年間支出額から目標額を逆算**: 想定生活費(年間支出額)を入力し、4%ルールなど任意の係数から必要資産額を自動算出した上で到達予測

達成度(現在資産 ÷ 目標資産)をゲージ等で可視化し、現在のペースに基づく到達予測日を算出する。

### 4.7 想定利回り・不動産時価・リスク等の手動設定

- 資産クラスごとの想定利回り、リスク値、不動産時価などを手動で設定できる
- 用途は以下の両方
  - 将来予測(シミュレーション)の入力パラメータとして使用
  - ダッシュボード上でリスク度合いなどを可視化(タグ・アイコン等)する際の表示用データとして使用

## 5. 非機能要件

- **アダプティブデザイン**: PC/タブレット/スマートフォンでの利用を想定し、画面幅に応じたレイアウト最適化を行う
- **拡張性**: 資産分類・不動産の管理項目など、今後の仕様追加を見越してマスタデータ／スキーマの拡張がしやすい設計とする
- **セキュリティ**: 個人の資産・金融情報を扱うため、Firebase Authenticationによる認証を必須とし、Firestoreのセキュリティルールでユーザー単位のデータアクセス制御を行う

## 6. 開発体制・ツール

- 開発にはClaude Code(AIコーディング支援ツール)を契約して活用する

## 7. MVPスコープとフェーズ分け

早期リリースを優先し、MVPは以下のように狭いスコープから開始する。

| フェーズ | 内容 |
|---|---|
| **Phase 1(MVP)** | Firebase Authentication認証、手動CSVアップロード(資産残高推移)、基本ダッシュボード(総資産推移グラフ、分類別内訳円グラフ) |
| **Phase 2** | 入出金明細CSV取込、収支サマリ(月次収支・費目別支出) |
| **Phase 3** | 不動産管理機能(物件登録、時価・ローン残高管理、利ざや自動計算) |
| **Phase 4** | FIRE目標設定・達成度ゲージ・到達期間予測、想定利回り/リスクの手動設定とシミュレーション反映 |
| **Phase 5(将来検討)** | マネーフォワード定期自動取得への対応、SaaS化(マルチテナント・権限モデル設計) |

## 8. 今後の検討事項(オープン課題)

- マネーフォワード定期自動取得の実装方式(公式API/スクレイピング等)の選定
- 将来のSaaS化に向けた権限モデル・マルチテナント設計
- ホスティング先の確定(Vercel / Firebase Hosting 等)
- UIデザインの詳細(配色・チャートライブラリ・CSSフレームワーク等)
- 不動産の複数ローン紐付けなど、より詳細な構成への対応要否
