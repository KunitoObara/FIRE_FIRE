# 画面要件定義書:ダッシュボード・データ管理系画面(B1〜B4)

## 1. 位置付け

本ドキュメントは [画面一覧・画面遷移図](./screen-list-and-transitions.md) 2.2節のダッシュボード・データ管理系画面(B1〜B4)について、画面ごとの要件を詳細化したものである。機能全体の方針は [FIRE-FIRE 要件定義書](./fire-asset-management-requirements.md) 4.2〜4.4節を参照。

## B1. ダッシュボード画面

- **画面目的**: ログイン後のトップ画面。資産状況・FIRE達成度・収支状況を俯瞰する

| 区分 | 項目 |
|---|---|
| 表示項目 | 資産推移グラフ(折れ線)、分類別内訳(円グラフ)、FIRE達成度ゲージ/到達予測日、収支サマリ(当月収支・費目別支出)、直近CSV取込日時、(A8経由のログイン時のみ)Googleアカウント連携の失敗通知 |
| 入力項目 | 分類軸切替セレクタ([B4](#b4-資産分類マスタ設定画面)で登録した分類から選択)、表示期間切替(例:1年/3年/5年/全期間) |
| 主な操作 | 分類軸切替、表示期間切替、「CSVを取り込む」ボタン、各ウィジェットからの詳細画面遷移 |

**分類軸の切り替えが及ぶ範囲**

分類軸切替セレクタは、**資産推移グラフと分類別内訳の両方**に反映する。分類軸は「総資産ポートフォリオに加えて切り替えられるポートフォリオの単位」であり([要件定義書](./fire-asset-management-requirements.md) 4.3)、内訳だけが切り替わって推移が総資産のまま残ると、同じ画面の2つのグラフが別の対象を指すことになるため。

- 資産推移グラフの見出しには選択中の分類軸名を添える(例:「資産推移(投資性資産)」)。「総資産推移」と固定で名乗ると、総資産以外を選んだときに中身と食い違う
- FIRE達成度ゲージと収支サマリは分類軸の影響を受けない。前者は目標資産額との比較、後者は入出金明細の集計であり、いずれも資産の分類軸とは別の軸のため

**Googleアカウント連携の失敗通知**

[A8 アカウント連携画面](./screen-requirements-auth.md) 経由でログインした場合、Googleアカウントの連携が失敗することがある。A8には連携を実行するタイミングが2つある(2FA登録済みなら**A5の検証成功後**、2FA未登録ならパスワード検証時点で**その場で**実行しA3へ進む)が、**どちらの分岐の失敗もこの通知の対象**とする。連携の成否にかかわらずサインイン自体は成立しているためログインはやり直させず、B1到達時に一過性の通知(トースト)で連携できなかったことを伝える。

- 失敗の要因はGoogle資格情報の期限切れ、`auth/credential-already-in-use`(そのGoogleアカウントが別のFIRE-FIREアカウントで使用済み)、通信失敗などを想定する。いずれもサインインは成立しているため扱いは同じ
- 文言は「Googleアカウントの連携ができませんでした。アカウント設定からやり直せます」のように、ログイン自体は成功していることが伝わる形にする
- 通知はその場の1回のみとし、以降のログインでは繰り返さない(連携していない状態自体はエラーではないため)
- 「1回のみ」は**そのログインフローの中で1回**という意味で、通知済みフラグをFirestoreやカスタムクレームに永続化しない。連携失敗はA8を経由したログインの直後にしか起こらず、A8の連携セッションと同じくメモリ上で引き回せば足りる
- リロード等で通知を見逃しても行き止まりにはならない。連携に失敗したアカウントはGoogleが未連携のままなので、次にGoogleログインを試みれば再び `auth/account-exists-with-different-credential` となり **A8 アカウント連携画面** に到達して連携をやり直せる。したがってこの通知は [A8-2] のB10側UI(連携状況の確認・やり直し)がリリースされていなくても成立し、[A8] 単体でリリースできる
- B10の連携アカウント管理は「現在どのログイン方法が使えるか」を確認・変更するための画面であり、連携失敗からの復帰手段としては必須ではない
- 連携のやり直しは **B10 アカウント設定画面** の連携アカウント管理で行う。B10側は未実装で、Trelloカード [A8-2] のスコープ([screen-requirements-account.md](./screen-requirements-account.md)「連携アカウントの管理」)

**遷移条件**

- 「CSVを取り込む」ボタン押下 → **B2 CSV取込画面** へ遷移
- 収支サマリの「詳細を見る」押下 → **B3 収支明細一覧画面** へ遷移
- FIRE達成度ゲージの「目標を設定する」押下 → **B8 FIRE目標設定画面** へ遷移
- 共通ヘッダー/サイドバーから他の主要画面へ自由に遷移可能

## B2. CSV取込画面

- **画面目的**: マネーフォワードCSV(資産残高推移/入出金明細)をアップロードし取込む

| 区分 | 項目 |
|---|---|
| 表示項目 | 取込種別タブ(資産残高推移/入出金明細)、直近の取込履歴、プレビューエリア |
| 入力項目 | CSVファイル選択 |
| 主な操作 | 「ファイルを選択」、プレビュー確認後「取込を実行する」ボタン、「キャンセル」 |

**遷移条件**

- ファイル選択後、パース成功 → プレビューエリアに取込対象データ(件数・期間・サンプル行)を表示し、実行前確認を求める
- パース失敗(形式不正) → エラー表示、取込不可のまま画面に留まる
- プレビュー確認後「取込を実行する」押下 → データ反映処理を実行し、完了メッセージを表示(画面に留まり連続アップロード可能)
- 「キャンセル」押下 → プレビューを破棄し、ファイル未選択状態に戻る

## B3. 収支明細一覧画面

- **画面目的**: 入出金明細CSVから取り込んだ個々の取引データを一覧・検索する

| 区分 | 項目 |
|---|---|
| 表示項目 | 取引一覧(日付・費目・金額・口座・摘要) |
| 入力項目 | 絞り込み条件(期間、費目、口座、キーワード検索) |
| 主な操作 | 絞り込み、並び替え(日付/金額) |

**遷移条件**

- 「CSVを取り込む」ボタン押下 → **B2 CSV取込画面** へ遷移
- 取引データの編集・削除機能は本ドキュメントの対象外とする(参照専用画面)

## B4. 資産分類マスタ設定画面

- **画面目的**: 資産分類軸(総資産、純金融資産、投資性資産等)をユーザーが追加・編集・削除できる

| 区分 | 項目 |
|---|---|
| 表示項目 | 登録済み分類一覧(分類名、集計対象の口座/資産種別の紐付け状況) |
| 入力項目 | 分類名、集計対象(口座/資産種別の選択、複数選択可) |
| 主な操作 | 「新規分類を追加」ボタン、既存分類の編集、削除 |

**遷移条件**

- 新規追加・編集の保存 → 一覧に反映し、**B1 ダッシュボード画面** の分類軸切替セレクタにも反映する
- 削除操作時、既存の資産データが紐づいている分類は削除を禁止し、エラーメッセージを表示する
